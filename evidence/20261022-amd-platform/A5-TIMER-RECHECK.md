# A5 定时器复测（2026-10-22 13:50 CST，S2 生效后）

目的：确认在 USB S2 稀疏 map + timer 补丁的当前组合下，定时器行为**没有回归**，并与
`docs/handoff-amd-timing-nvram.md`（2026-10-21）的读数做同口径对比。

只读测量：未改 EFI、未重启、未加载/卸载 kext；探针是用户态程序。

## 结论

1. **8 倍等待异常没有复现**；当前读数与 10-21 的记录同量级。
2. **1.25x 只出现在“普通线程 + mach_wait_until”路径（mode 0）**，是内核定时器合并
   （coalescing）的正常表现，不是时钟换算错误：
   - 同一 deadline 用忙等（busy-spin）测，比值 **1.000x**，说明 `mach_absolute_time`（TSC）准确；
   - 同一 deadline 用 `THREAD_TIME_CONSTRAINT_POLICY`（mode 1，音频 HAL 走的路径）测，**1.000–1.004x**。
3. 音频相关判据（512 帧 @48 kHz ≈ 10.67 ms，实时约束路径）因此满足计划 §5.5 的 `<1.1×`。

## 建议

- 不改 timer 补丁。它只允许 Darwin 24.6.0，升级系统后必须重新评估
  （见 `docs/macos-update-checklist.md`）。
- 不再把 “mode 0 的 1.25x” 当缺陷跟踪；若要继续研究，方向是“让音频线程稳定拿到时间约束策略”，
  而不是改 `busFCv2t` 常数。
